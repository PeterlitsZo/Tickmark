# Tickmark mobile

A React Native app for recording completed activities. The calendar uses a single-day timeline: hold an empty area, drag out a time range, release, then describe what you did. Entries can also be added with the **+** button, browsed by date on the timeline, edited, and permanently deleted. Bottom tabs separate **Calendar** and **Todos**. Todos are global across dates; create, edit, complete, reopen, or delete them from their own page. Tab switches retain in-session drafts, scroll positions, and completion disclosure. The legacy `/entries` route redirects to Calendar.

Entries have named, colored categories. Open category management from the calendar menu or entry editor. The last category used for a successful creation is remembered on this device per API origin; missing preferences fall back to the lowest available ID. An empty category library lets the server create Default. Category-only edits, dragging, resizing, and uncertain-save reconciliation retain category IDs.

Writes are never retried automatically. After an interrupted write, use **Check status**, inspect the refreshed data, and explicitly allow another change. Drafts survive navigation within the running app; they are not a persistent offline queue.

## Requirements

- Node.js 22.13 or newer and npm. Dependencies are locked in `package-lock.json`; use `npm ci`.
- iOS: macOS, Xcode with an installed simulator runtime, and CocoaPods. A physical iPhone also requires a development signing team and Developer Mode.
- Android: Android Studio / Android SDK, a compatible JDK, and an emulator or a device with USB debugging enabled. Set `ANDROID_HOME` to your SDK directory.

This project uses Expo SDK 58. You can preview it with an SDK 58-compatible Expo Go app, or install a native development build using the instructions below.

## Start on a phone or simulator

Run commands from `mobile/`:

For a quick preview, install an SDK 58-compatible Expo Go on your phone, then run:

```sh
npm ci
cp -n .env.example .env
npm run start:go
```

Scan the terminal QR code with your phone. The phone and computer must be on a reachable LAN. This workflow was exercised with Expo Go 58.0.7 on the iOS simulator and 58.0.5 on the Android emulator. If your phone's available Expo Go does not support SDK 58, use a development build instead.

To build and install the native development app:

```sh
npm ci
cp -n .env.example .env
npm run ios -- --device
# Or, with an Android emulator/device available:
npm run android -- --device
```

Choose the target when prompted. These commands generate the ignored native project, build and install the app, and start Metro. Native directories are generated by Expo; keep permanent configuration in `app.json` or config plugins.

For later development sessions, run `npm start` and open the installed Tickmark development app. A phone must be able to reach Metro on your computer (normally the same LAN); the deployed API itself is available over HTTPS from any internet connection. Development builds require Metro. Use a preview build for an independently running app.

`EXPO_PUBLIC_API_BASE_URL` is the API origin. The client appends `/api/v1`. Restart Metro and reload the app after changing this value. Public Expo environment variables are embedded in the app and must not contain secrets.

The existing server is unauthenticated and has no per-user data isolation. All clients using the same server access the same entries.

## Local server without touching production data

Follow `../server/README.md` to install the server tools. To use a separate local database, run from `server/`:

```sh
npx wrangler d1 migrations apply DB --config cloudflare-worker/wrangler.example.jsonc --local --persist-to /tmp/tickmark-mobile-d1
npx wrangler dev --config cloudflare-worker/wrangler.example.jsonc --local --persist-to /tmp/tickmark-mobile-d1 --ip 0.0.0.0 --port 8790
```

Then set the mobile API origin:

- iOS simulator: `http://127.0.0.1:8790`.
- Android emulator: `http://10.0.2.2:8790`, or use `adb reverse tcp:8790 tcp:8790` and `http://127.0.0.1:8790`.
- Physical phone: `http://<computer-LAN-IP>:8790`; phone and computer must share a reachable network. A phone's `localhost` points to the phone itself.

Local HTTP is for development builds. Preview and production builds should use the HTTPS server. No CORS change is needed for the native app. A web build is not part of this release.

## Interaction and data rules

- Scroll normally to browse hours. Hold an empty area for 300 ms to begin a selection, drag in either direction, and release to open the editor. Selection snaps to five minutes; holding without moving starts with fifteen minutes. Drag near the top or bottom to scroll while selecting.
- Creating and editing a form writes only on **Save**. Closing a changed draft asks before discarding it. Date and time use a themed community picker inside the same card: **Done** updates the draft, **Cancel** discards picker changes. Existing entries do not automatically open the keyboard.
- Tap a block to edit. Long-press an existing block to select it, continue dragging to move it, or release without moving to expose its start/end handles. Drag a handle to adjust that endpoint. Moving preserves the original duration and seconds; resizing leaves the other endpoint unchanged. A changed drag commits once on release. A hold without movement does not write. Dense short entries offer a local chooser.
- Changing only a title preserves the original timestamps. Cross-day blocks are clipped for drawing only. Time rows emphasize the time, with compact dates beside them. The picker exposes UTC offsets and offers an explicit alternate occurrence for repeated local hours.
- Day boundaries follow the device time zone. DST days can contain 23 or 25 hours. API timestamps are integer seconds; IDs remain strings. Zero-duration entries display as time-point markers. Overlapping blocks use separate columns, including short blocks that need a minimum visual height.
- Date arithmetic uses `@date-fns/tz` with the IANA zone reported by `expo-localization`. This keeps date boundaries and UTC offset labels consistent after changing the device zone while the JavaScript runtime remains alive.
- The calendar uses a shared query cache and selected date. Writes refresh all cached date ranges. Returning to the foreground or reconnecting refreshes data. The old `/entries` route redirects to the calendar.
- A pending PUT locks that entry. Uncertain results retain their proposed times while the client reads the old and new ranges to check the server result. If confirmation is unavailable, the status card offers another check and an explicitly confirmed retry. Definite rejection restores the confirmed data; 404 removes the missing entry.
- POST is never automatically retried. After a connection failure, **Check whether it saved** searches for an exact matching entry before another save is allowed. The API has no idempotency keys, so a delayed write cannot be conclusively ruled out by a single check.
- Offline data is limited to the current in-memory cache. There is no persisted offline queue. Drafts survive recoverable request failures within the current app session, not process termination.
- Deletes are permanent and require confirmation. Concurrent edits follow the server's last-write-wins behavior.

## Source map

- `app/`: Expo Router calendar, root stack, and legacy Entries redirect.
- `src/api/entries.ts`: request timeout, DTOs, CRUD, and structured API errors.
- `src/features/entries/`: editor container, compact form, draft session, shared mutations, and query/cache helpers.
- `src/features/calendar/`: timeline composition, block/handle views, gesture sessions, edge scrolling, and pure time/layout geometry.
- `src/lib/time.ts`, `pickerTime.ts`: date boundaries, formatting, validation, and the picker-to-IANA-time adapter.
- `src/components/`, `src/theme/`: shared interface components and visual tokens.
- `assets/icon-directions/`: approved Timeline icon, alternative direction, review previews, and regeneration instructions.

## Checks

```sh
npm run typecheck
npm run lint
npx expo install --check
npx expo-doctor
npm run export
```

`export` compiles both native JavaScript bundles; it does not produce an APK or an iOS binary. No automated tests or test dependencies are included, as requested by the repository instructions.

Manual acceptance should cover creation by drag and Add, ordinary scrolling, reverse and edge dragging, cancellation, empty/long/Unicode titles, title-only editing, cross-date edits, overlapping/zero-duration/cross-midnight entries, date navigation, deletion confirmation, missing entries, offline recovery, keyboard layout, and app relaunch. Perform writes only against the isolated local service or a dedicated staging service. Verify DST dates in a time zone that observes DST. Device-specific behavior should be checked on the intended physical phone before distributing a build.
